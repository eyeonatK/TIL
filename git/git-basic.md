# Git 기본 아키텍처 및 핵심 워크플로우

Git은 소스코드의 변경 이력을 추적하고 관리하는 분산 버전 관리 시스템(VCS)입니다.

## 1. 3단계 데이터 흐름

작업 파일이 버전으로 기록되어 원격 서버로 전달되기까지 세 가지 단계를 거칩니다.

1. **Working Directory**: 사용자가 직접 코드를 작성하고 수정하는 실제 로컬 작업 영역
2. **Staging Area**: 다음 커밋에 포함할 파일들을 선별하여 등록하는 중간 준비 영역 (Index)
3. **Repository**: 로컬에 완전한 스냅샷 형태로 기록된 버전 데이터베이스

## 2. 핵심 명령어 정의

### git add
- **역할**: 변경 사항 중 기록할 대상을 Staging Area에 등록합니다.
- **예시**:
bash
git add README.md   # 특정 파일 등록
git add .           # 변경된 모든 파일 등록

### git commit
- **역할**: Staging Area에 등록된 파일들의 상태를 하나의 영구적인 버전(스냅샷)으로 확정합니다.
- **옵션 `-m`**: 커밋 메시지(Message)를 별도의 편집기를 거치지 않고 인라인으로 즉시 전달하는 옵션입니다.
- **예시**:
bash
git commit -m "docs: Git 기본 개념 정리"

### git push origin main
- **역할**: 로컬 저장소에 누적된 커밋들을 원격 저장소로 업로드하여 동기화합니다.
- **`origin`**: 원격 저장소(GitHub 레포지토리 주소)에 기본으로 부여되는 식별 별칭(Alias)
- **`main`**: 프로젝트의 기본 기준선이 되는 메인 브랜치(Branch)
- **예시**:
bash
git push origin main
