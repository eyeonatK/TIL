# 네트워크 및 HTTP 통신 기초

웹 환경에서 클라이언트와 서버가 데이터를 주고받기 위한 기본 통신 규약, 계층 구조, 식별자 체계(IP, Port, DNS, URI) 정리.

---

## 1. 웹 통신 아키텍처 및 IP

웹은 요청(Request)을 보내는 **클라이언트(브라우저 등)**와 결과를 돌려주는 **웹 서버** 간의 Client-Server 모델로 동작한다.

* **IP 주소 (Internet Protocol Address)**: 복잡한 인터넷 망에서 통신 장비(호스트)를 유일하게 식별하는 고유 번호 (IPv4: 32비트, IPv6: 128비트).
* **패킷 (Packet)**: 네트워크를 통해 전달되는 데이터의 기본 전송 단위 (출발지 IP, 목적지 IP, 전송 데이터 포함).

### IP 프로토콜의 한계
* **비연결성**: 대상 서버가 꺼져 있거나 불능 상태여도 패킷을 일방적으로 전송함.
* **비신뢰성**: 네트워크 중간 노드 장애 시 패킷 유실 가능, 패킷 전송 순서 보장 불가.
* **프로그램 구분 불가**: 동일한 IP 내에서 여러 프로그램이 동시에 통신할 때 수신 대상을 가려내지 못함.

---

## 2. 전송 계층 프로토콜 (TCP vs UDP)

IP 프로토콜의 한계를 보완하여 애플리케이션 간 통신을 제어한다.

| 비교 항목 | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
| :--- | :--- | :--- |
| **연결 방식** | **연결 지향** (3-Way Handshake) | **비연결 지향** (연결 수립 과정 없음) |
| **신뢰성** | 데이터 전달 확인 및 패킷 전송 순서 완벽 보장 | 전송 보장 없음 (패킷 유실 가능) |
| **속도** | 상대적으로 느림 (제어 오버헤드 발생) | 매우 빠름 (단순 헤더 구성) |
| **사용 사례** | 웹 통신(HTTP/HTTPS), 파일 전송(FTP), 이메일 | 실시간 스트리밍, DNS 질의, 온라인 게임 |

### TCP 3-Way Handshake
데이터를 전송하기 전, 양단 간 논리적 연결 통로를 확립하는 3단계 검증 과정.

```text
[ Client ]                             [ Server ]
    │                                      │
    ├─── 1. SYN (접속 요청) ───────────────>│
    │                                      │
    │<── 2. SYN + ACK (수락 및 확인 요청) ───┤
    │                                      │
    ├─── 3. ACK (최종 연결 확인) ──────────>│
    │                                      │
    ▼ [ 연결 수립 (Established) 후 데이터 전송 시작 ] ▼
```

## 3. 포트(Port)와 DNS

* **Port**: 한 대의 컴퓨터(단일 IP) 안에서 동작하는 여러 애플리케이션 서비스를 충돌 없이 식별하기 위한 논리적 통로 (0 ~ 65535).
  * **HTTP**: `80`
  * **HTTPS**: `443`
  * **SSH**: `22`
  * **PostgreSQL**: `5432`
* **DNS (Domain Name System)**: 기억하기 어려운 숫자로 된 IP 주소를 사람이 읽기 쉬운 문자 형태(예: `google.com`)로 변환해 주는 전화번호부 역할의 시스템.

## 4. URI (Uniform Resource Identifier) 구조

인터넷상의 특정 자원을 식별하고 접근 위치를 나타내는 표준 규격.

```text
[https://api.agent.com:443/v1/documents?keyword=python#section1](https://api.agent.com:443/v1/documents?keyword=python#section1)
└─┬─┘   └──────┬─────┘ └─┬─┘ └────┬────┘ └──────┬──────┘ └───┬────┘
프로토콜    호스트(도메인)    포트     리소스 경로      쿼리스트링      프래그먼트
(Scheme)     (Host)       (Port)     (Path)        (Query)      (Fragment)
```

| 구성 요소 | 설명 | 예시 |
| :--- | :--- | :--- |
| **Protocol (Scheme)** | 자원에 접근하기 위한 통신 규약 | `https`, `http` |
| **Host** | 접근할 서버의 도메인 이름 또는 IP 주소 | `api.agent.com` |
| **Port** | 접속할 서비스의 포트 번호 (표준 포트는 주로 생략) | `:443` |
| **Path** | 웹 서버 내에서 자원이 위치한 계층적 경로 | `/v1/documents` |
| **Query String** | `key=value` 쌍으로 서버에 전달하는 추가 매개변수 | `?keyword=python` |
| **Fragment** | 문서 내 특정 앵커/북마크 위치 가리킴 | `#section1` |
